# bobiDelight 1.4.0 更新日志

发布日期：2026-05-06

## 概览

1.4.0 这一版主要完成了作物资源补完、双端资源闭环修复、构建链路稳定化，以及文档与版本信息同步。相较 1.3.0，本次更新把若干“已注册但资源表达不完整”的内容推进到了可直接发版的状态。

当前项目内容规模保持为：33 种可种植作物、33 种野生作物、15 个 FeastBlock。

## 资源与美术

- 新增并重绘了 5 套重点作物贴图：玉米、大蒜、姜、黄瓜、茄子。
- 上述 5 套内容同时覆盖了以下资源类型：
  - crop stage0 / stage4 / stage5 / stage6 / stage7
  - wild crop
  - produce item
  - seeds item
- 贴图已同步写入 Fabric 与 Forge 双端资源目录，避免平台间资源不一致。
- 为小白菜、山药、香菇补齐了自定义 crop cross 模型，修复旧的 vanilla crop parent 在现有贴图表现下的显示不一致问题。
- 为小白菜袋装、山药箱装、香菇箱装补齐 block / item model 以及对应贴图。
- 补齐了 Hot Pot 相关 block stage、side、bottom 以及 item 贴图资源，完善整套餐食方块的显示闭环。

## 数据与资源闭环

- 在 Fabric 与 Forge 双端新增并统一了以下标签：
  - data/bobidelight/tags/blocks/crops.json
  - data/bobidelight/tags/blocks/wild_crops.json
  - data/bobidelight/tags/items/seeds.json
  - data/bobidelight/tags/items/crops.json
  - data/bobidelight/tags/items/farmersdelight_seeds.json
  - data/bobidelight/tags/items/compostables.json
- 这批标签补齐后，作物、野生作物、种子与堆肥分组的资源组织更加完整，后续继续扩作物时不需要再为基础标签补洞。

## 逻辑与兼容性修复

- Fabric / Forge 两端入口都改为显式调用 `ModItems.init()`，替换依赖静态字段副作用的初始化方式，降低内容未注册或 IDE 导入顺序异常的风险。
- `FeastBlock` 增加了 `canSurvive` 支撑面检查，避免筵席类方块在失去下方方块后仍异常悬空。
- `FeastBlock` 的进食逻辑移除了重复的 `player.canEat(false)` 拦截，使其行为更接近 Farmer's Delight 同类方块的预期。
- `ModBlocks.getCutoutBlocks()` 改为同时覆盖 BushBlock 与 FeastBlock，统一两类方块的 cutout 渲染收集逻辑。

## 构建与工程修复

- 移除了 Fabric / Forge 构建脚本中的 BMCLAPI Maven 镜像，规避部分环境下依赖解析 403、VS Code Java 导入卡死等问题。
- Forge 侧新增 `processResources` 展开 `${mod_version}`，使 `META-INF/mods.toml` 能正确注入当前版本号。
- Forge 的 `mods.toml` 版本字段统一改为 `${mod_version}`，避免 jar 版本与 Gradle 版本源不一致。
- 贴图生成脚本修复了两类 Windows 环境问题：
  - PowerShell 二维坐标数组写法导致的 `op_Addition` 运行时错误
  - 直接保存 PNG 到目标路径时生成 reparse point，进而导致 Gradle 报 `not a regular file`
- 现有生成流程改为先写临时 PNG，再用字节流重写正式路径，生成结果可被 Gradle 正常处理。

## 文档与开发辅助

- 校正了 README 与植物生成指南中因实现扩容而产生的文档漂移，确保内容统计与当前注册结果一致。
- 植物生成指南和设计文档镜像现在都同步到 1.4.0，避免版本号先发版、说明文档仍停在旧版本。
- 新增了 nanobanana 生图指令文档，便于后续继续通过外部参考图驱动作物贴图清稿。
- 新增 Farmer's Delight addon 参考 skill 与本地参考语料整理脚本，方便后续针对附属模组做方案设计、评审和实现。

- 已执行：`./gradlew.bat build --no-daemon`
- 验证结果：构建成功，Fabric / Forge 双端资源处理通过。
